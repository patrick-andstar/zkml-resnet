## 1. 为什么第 2、3 条必须先修

这两条其实是一个错误的两个面：v2/v3 把「哪些 tensor 在加载时就该存在」压缩成一个 `referenced_tensor_ids`，而这个集合同时装了三种语义完全不同的 ID：

| 集合 | 什么时候存在 | 装了什么 |
|---|---|---|
| 初始张量 | DAG 之前 | 权重、常量 |
| 模型输入 | 请求时提供 | input |
| 各层产出 | 逐层执行时 | 中间激活、最终输出 |
| commit 观察点 | before 在 DAG 前、after 在后 | 视配置 |

把它们混在一起，就同时炸出两个问题：

**（a）合法稀疏图被误拒。** 最小例子：初始真实 ID `{0,2}`，L0 输入 0、输出 1，最终输出 1。加载期检查认可「1 由 L0 产出」，但 `tensor_map_to_vec` 在把 map 转成按 ID 索引的 Vec 时，位置 1 是空洞，而它又出现在 `referenced_tensor_ids` 里 —— 于是提前 panic。**未来才产出的张量，被要求在这一刻已经赋值。**

**（b）瘦配置验证被误杀。** `converter` 会故意清空 `config.tensors`，`verify_circuit` 走 `generate_from_msgpack(config, false)` 后直接读 VK 验证，不做权重前向。v2 无条件要求「所有层的数据依赖都在 `config.tensors ∪ 模型输入` 里」，于是把缺省的权重视为缺失，verifier 入口直接崩。

更细一层：即使绕开上面的检查，`tensor_map_to_vec` 开头就对空表做 `min_by_key(...).unwrap()`，空表必 panic。**这是 v2 破坏瘦配置入口的第二个独立原因**，v2 没意识到。

## 2. v4 的做法

### 2.1 三段生命周期

```text
initial           = 初始张量 ∪ 模型输入        （DAG 前真实存在）
produced          = 各层 out_idxes            （按层推进，含尚未执行的）
required_initial  = 被引用 − produced         （只有它必须在初始 map 里）
```

`tensor_map_to_vec` 只对 `required_initial_ids` 里的空洞硬失败。未来层输出的空洞是合法空槽，会被执行到的层填上。

这样第（a）个反例就通了：`referenced = {0,1}`，`produced = {1}`，`required_initial = {0}` —— 位置 1 的空洞不再触发 panic。

### 2.2 两种加载模式

```rust
let load_mode = if config.tensors.is_empty() {
  LoadMode::ConfigOnly
} else {
  LoadMode::FullWitness
};
```

| 模式 | 触发 | 检查内容 |
|---|---|---|
| `FullWitness` | `tensors` 非空 | 结构检查 + 逐层核对「输入此刻确实可用」 |
| `ConfigOnly` | `tensors` 为空 | 只做结构检查；`required_initial` 置空 |

结构检查两种模式都做，因为它们不依赖权重：

1. 同一 ID 被两层重复产出 → 拒绝；
2. 层输入引用了**自身或更晚**的层产出 → 拒绝（这是「未来引用」的真正判据）；
3. 最终输出必须是模型输入或某层产出；
4. `commit_before` 只能引用 `initial`；`commit_after` 允许 `initial ∪ produced`。

第 2 条是这次的关键补强：**它不需要知道权重是否存在**，所以在 config-only 下依然能拦住"引用未来输出"这类真错误。v2 用「输入必须在 available 里」来表达同一件事，但那个表达在无权重时会误伤。

### 2.3 空表早返回

```rust
if tensor_map.is_empty() {
  return Ok(vec![]);
}
```

放在 `min_by_key(...).unwrap()` 之前。这是修第 3 条的另一半。

### 4.1 ConfigOnly 与 commit 的兼容性：v4 没闭合

这一条是 v4 自己引入的，必须单独说清。

`commit_before` 的语义是「在 DAG 之前承诺某个张量」。在 **FullWitness** 模式下，权重与常量都在 `initial_ids` 里，所以「合法地在 DAG 前承诺一个权重」是通的。

但在 **ConfigOnly** 模式下：
- `config.tensors` 为空 ⇒ `initial_ids` 只剩**模型输入**；
- 而 `commit_before` 的检查仍然是 `if !initial_ids.contains(idx) { panic }`；
- 于是「完整模型里合法承诺某个权重」的配置，在瘦配置验证下**仍会被拒**。

后果的范围要说准：**这不表示默认的 `--no-commit` 目标已经失败**（那条路径下 `commit_before` 为空，检查根本不触发）。它表示的是——**「config-only 与 commit 兼容」这句话现在还不能说**。

修法方向（留到下一批，不为了本次编译扩大改动面）：`commit_before` 在 ConfigOnly 下应只校验「引用的 ID 不是未来层产出」，而不是「必须在 initial 里」；或者显式记录 `unresolved_commit_ids` 并降级为警告。二者都要连带补一条回归用例。


另外两处已知折中，写在这里而不是藏在代码里：

1. **`LoadMode` 是从 `tensors.is_empty()` 推断的，不是显式参数。** 这样做避免改动 `verify_circuit` 的现有调用签名，但代价是语义隐式：将来若出现「空权重却要求完整校验」的调用，会静默降级成结构检查。要根治得改成显式入参，那是一次接口变更，需要单独批准。
2. **`required_initial` 在 config-only 下置空**，意味着该模式**不做任何数据依赖校验**。这是有意的：权重不在请求里，本来就没有可校验的数据。但不能把它读成"config-only 也验证了依赖关系"。
