## 3. 工具链：遇到并解决的两个问题

### 3.1 官方源太慢 → 换镜像

`static.rust-lang.org` 实测出现过 12 KB/s（120 s 只下到 1.4 MB / 21 MB）。测速结果：

| 源 | 下载 21 MB 耗时 |
|---|---|
| 中科大 `/rust-static` | ~2.9 s |
| 清华 `/rustup` | ~1.8 s |
| rsproxy | ~2.6 s |
| 官方 | 不稳定，曾 120 s 未完成 |

最终：rustup 安装器用清华，**工具链 dist 用中科大**（清华镜像没有带日期的 nightly manifest，`2024-05-01` 直接 404，只有中科大和官方有）。

### 3.2 旧工具链装不进新依赖 → 调整工具链

第一次选 `nightly-2024-05-01`（rustc 1.80.0-nightly），`cargo fetch` 报：

```text
error: failed to parse manifest at .../constant_time_eq-0.4.2/Cargo.toml
Caused by: feature `edition2024` is required
```

原因：源码没有 `Cargo.lock`，`serde = "1.0.152"` 这类写法会解析到 2026 年的最新版本（`serde 1.0.229`、`syn 3.0.10` 等），它们要求 `edition2024`。

处理：改用 `nightly-2026-11-01`（rustc 1.101.0-nightly, f9ceb4a4d 2026-10-31）。理由与代价：

- 代码里唯一的 nightly feature 是 `#![feature(int_roundings)]`，该特性自 1.73 已稳定，所以只需"任一现代 nightly"。
- 旧 halo2（2023）在 1.101 nightly 上编译**只出 3 个 warning，无 error**。
- **代价**：编译器和 LLVM 版本与论文不同，属于复现偏离，已记录；不影响协议正确性，但绝对时间不能与论文逐毫秒对比。

写入 `src/rust-toolchain.toml`：

```toml
[toolchain]
channel = "nightly-2026-11-01"
profile = "minimal"
```

隔离安装位置：`RUSTUP_HOME=/root/autodl-tmp/zkml-repro/env/rustup`、`CARGO_HOME=.../env/cargo`，未污染系统与 conda base。

依赖镜像写入 `env/cargo/config.toml`：

```toml
[source.crates-io]
replace-with = "rsproxy-sparse"
[source.rsproxy-sparse]
registry = "sparse+https://rsproxy.cn/index/"
[net]
git-fetch-with-cli = true
```

GitHub 依赖走 AutoDL 学术加速（`source /etc/network_turbo`），并把 `rsproxy.cn` 加入 `no_proxy`，避免代理拖慢 crates 下载。

## 5. 构建

```bash
cd /root/autodl-tmp/zkml-repro/src
CARGO_BUILD_JOBS=4 cargo build --release --locked \
  --target-dir /root/autodl-tmp/zkml-repro/target \
  --bin test_circuit --bin time_circuit --bin verify_circuit
```

结果：**rc=0，1m11s**。产物：

## 6. 过程中的两个操作事故（已修正）

1. **Git Bash 路径转换**：`put ... "/root/..."` 被 MSYS 转成 `D:/WorkBuddy/.../root/...`，导致远端建出一棵 `/root/D:/WorkBuddy/...` 垃圾目录。
   处理：删除该目录，之后所有远端路径命令加 `MSYS_NO_PATHCONV=1`。**没有触碰任何既有项目文件。**
2. **长命令被工具超时杀掉**：`rustup-init` 首次尝试因下载慢+工具 10 分钟上限被 SIGTERM，无残留。改为分步执行、先测速再下载。
