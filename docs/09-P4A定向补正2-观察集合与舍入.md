## 1. 4b：PADV2 的观察集合

### 问题

v2 的 `_validate_padv2_subgraph` 只把 `layers[-1]['out_idxes']` 当公开输出。这漏掉一类图：**原图同时输出 Pad 与 Pool**——Pad 仍然只被 Pool 消费、导出子图只公开 Pool，但 `commit_after` 取的是整图 `output_details`，Pad 会被额外承诺。此时把 `-inf` 换成 0 就不再等价，而 v2 会放行。

### 做法

新增 `_observation_tensors(layers)`，先形成集合再判定：

```text
观察集合 = graph.Outputs() 全部          # 即使没 expose_output，这也是真实输出
         ∪ layers[-1]['out_idxes']      # 仅 expose_output 时
```

`commit_after` 取的正是 `output_details`，与 `graph.Outputs()` 等价，因此这一项覆盖了"被承诺观察"。

消费者数量仍按子图重算，要求恰好 1 个且等于转换时记录的 MaxPool；证据里新增 `observed_tensor_ids`，`checked_against` 改为 `graph_outputs+exported_subgraph+single_consumer`。

**`commit_before` 为什么不用单独并进来**：它由 kept 常量与模型输入构成，而 Pad 输出是层产物。若它真被当常量收进 `keep_tensors`，说明它同时是图输出，已由第一项覆盖。这条推理写进了函数注释，不只写在文档里。

## 2. 5：元数据按位置过滤

### 问题

`_metadata_tensor_idxes` 返回的是 **tensor ID 集合**，调用点做 `[i for i in inp_idxes if i not in _meta]`。同一个张量若同时出现在数据位置和元数据位置，会被一起删掉。

最小反例：INT32 零常量 `t`，形状 `[2,2]`，`PAD([t, t])` 本来是无填充恒等；按 ID 删之后变成零输入。

### 做法

`_metadata_input_positions` 返回**位置**（`[1]` 而不是 `{7}`）。调用点直接读原始 `InputsAsNumpy()` 数组再按位置过滤，**不能用 `get_inputs`**——它会先剔掉 `-1`（可选输入），位置会错位：

```python
_raw_inputs = [int(x) for x in handle_numpy_or_literal(op.InputsAsNumpy()).tolist()]
inp_idxes = [t for p, t in enumerate(_raw_inputs) if p not in _pos_set and t != -1]
```

### 顺带补的静态常量检查

普通 `PAD` 的 `paddings` 与 `MEAN` 的 `axes` 原本直接 `interpreter.get_tensor(...)`，等于把**一次 invoke 的结果**冻结进 params。现在都走 `_static_constant`：有 producer 即拒绝，`Buffer()==0` 或空 buffer 也拒绝。

## 3. 6：舍入与缩放

### 3.1 舍入

`sign(x)*floor(abs(x)+0.5)` 在 binary64 上不是全域正确的 half-away：

| 输入 | 旧式 | 应为 |
|---|---|---|
| `0.5 − 2^-54` | `1`（`abs(x)+0.5` 先被舍成 1.0） | `0` |
| `2^52 + 1` | `2^52 + 2`（加 0.5 后 ties-to-even） | `2^52 + 1` |

改成"取整 + 判余数"：

```python
a = np.abs(x); fl = np.floor(a); frac = a - fl
return np.sign(x) * (fl + (frac >= 0.5).astype(np.float64))
```

对 `|x| < 2^53`，`floor` 与 `x − floor(x)` 都精确，余数比较不产生新舍入；`|x| ≥ 2^53` 时余数恒为 0，原样返回。

### 3.2 CUSTOM 缩放顺序

原写法 `_quantize_checked(weights * self.scale_factor, ..., already_scaled=True)`：`weights` 通常是 float32，`float32 * scale` 会**先在 float32 里舍一次**，之后的有限性与范围检查已经看不到丢掉的精度。

改为传原始权重、`already_scaled=False`，由 helper 先 `np.asarray(..., dtype=np.float64)` 再乘。

反例（已跑）：float32 权重 `1+2^-23`、`sf = 2^22−1`。精确乘积 `4194303.4999998808`，应舍为 **4194303**；float32 先乘得 `4194303.5`，再 half-away 得 **4194304**，错一位。

### 3.3 DIV

`scale_factor / div_val` 里 `div_val` 是 float32，直接相除同样先在 float32 舍。改为 `float(self.scale_factor) / float(div_val)` 在 float64 里算。

### 3.4 三条路径的复核对账

| 路径 | 传入 | `already_scaled` |
|---|---|---|
| 主循环 | 原始 FLOAT32 张量 | `False`（默认） |
| CUSTOM | 原始权重（改后） | `False`（改后） |
| DIV | 已算好的 `scale/div`（float64） | `True` |

`adjusted_tensors` 里的值会在主循环末尾**覆盖**同 ID 结果，所以不会二次乘 scale。这一条是对着源码逐行确认的，不是推断。

## 4. V4-G1：瘦配置的承诺兼容

### 问题

`ConfigOnly` 下 `tensors` 被清空，`initial_ids` 只剩模型输入。而 v4 仍要求 `commit_before` 的 ID ∈ `initial_ids`、`commit_after` 的 ID ∈ `initial ∪ producer`。于是完整模型里合法地在 DAG 前承诺一个权重，瘦配置下会被拒。

### 做法：阶段与存在性分开判

| 检查 | FullWitness | ConfigOnly |
|---|---|---|
| `before` 引用层产出 | **拒绝** | **拒绝**（阶段不可能） |
| `before` ID ∉ initial | 拒绝 | 记入 `unresolved_commit_ids` |
| `after` ID ∉ initial ∪ producer | 拒绝 | 记入 `unresolved_commit_ids` |

`unresolved_commit_ids` 是 `ModelCircuit` 的新字段，**只在 ConfigOnly 下可能非空**。它存在的意义就是：这些 ID 只是**被允许通过**，没有被验证过——不能描述成"依赖已验证"。

`after` 直接承诺初始常量的情形也一并覆盖了：瘦配置里该常量同样没有实体，同样进 `unresolved`。这就是"不能只修 before 就宣布兼容闭合"的具体落点。

明确没做的事：不改成"警告后放行"，不给 verifier 加回权重，不静默删除承诺组。
