## 关键结论（MNIST，k=15）

| 指标 | 实测值 |
|---|---|
| 核心验证 `verify_kzg` | **8.8 ms** |
| 完整验证请求（新进程、单 CPU） | **222.9 ms** |
| 其中 SRS 加载 | **185.5 ms（83%）** |
| 其中进程启动/退出残差 | ~21 ms |
| 其中 VK 读取 | 7.2 ms |
| 比值 完整请求 / 核心 | **25×** |

**最重要的一条**：端到端开销不是密码学成本，而是 `ParamsKZG::read` —— 它把 `g` 和 `g_lagrange` 两组各 `2^k` 个**未压缩**点全部读入并解码。读 4 MB 文件本身只要 3.2 ms，其余约 182 ms 全是逐点解码。

这条结论直接决定 128×128 的可行性：SRS 读取成本随 `2^k` 线性增长。按 k=15 实测外推（**估算，未实测**），k=28 时仅加载 SRS 约需 25 分钟、参数文件约 34 GB。也就是说 **"验证 < 1 s" 在这套代码上首先被参数加载挡住，而不是被配对运算挡住**。

## P4-A 一句话结论（2026-11-14 22:40，v1；解释部分已被 §2.8 复核推翻）

`MaxChip` 的归约缺陷是「一行把位置 `i` 与位置 `G+i` 配对、归约到 `G` 个输出就停、最后只取第 0 个」，返回值退化成「每 `G` 个位置取一个的同余类最大」：6 列 9 元素下恒等于 `max(x0,x2,x4,x6,x8)`，奇数下标全丢（0/1 穷举 512 例错 15 例）；最小反例仅 `[0,1] → 0`。候选修复分树形+collapse 两段，复刻验证 1..10 × {3,6,9,12} 全过且**行数更少**（6 列 9 元素 11→7）。另三个补丁（PADV2 图级保护 P1–P5、元数据依赖清理、数值编码边界）也 dry-run 通过。**本批不编译、不运行**，因此只能写「候选修复已准备」，不能写「已修复」。

## 勘误（P2A 实测，2026-11-14 20:15）

原文数字与解释一律保留，下面是实测纠正。依据：`03-P2A-量具校准与读取对照.md`、`manifests/mnist-p2a-calib-manifest.json`、`runs/p2a-calib1/`。

### E1. "其余约 182 ms 全是逐点解码" —— 错

同一 `ParamsKZG::read`、同一 `SerdeFormat`，只把未缓冲 `File` 换成 1 MiB `BufReader`，k=15 的 SRS 段 **187.8 ms → 6.18 ms**。慢的是 **524,288 次 8 字节 `read_exact` 系统调用**（每个 32 B 坐标 4 次，每个 G1 点 8 次，2×2^15 点），不是点解码。加缓冲后**剩下的 ≤6.18 ms 才是解码成本**。

### E2. "端到端开销不是密码学成本，而是 ParamsKZG::read" —— 结论对，归因错

开销确实在 `ParamsKZG::read`，但不在它做的密码学检查，而在它用的**读方式**。原文把"逐点解码"当成不可约成本，进而论证目标"在架构上达不到"，这一步不成立。

### E3. 外层 222.9 ms / 残差 ~21 ms —— 含量具误差

旧 `measure.py` 每 20 ms 轮询，本身带检测滞后。量具 v2.1（`wait4` 阻塞回收）实测外-内差稳定在 **6.0–6.9 ms**，与 exec/动态链接/退出同量级。旧残差里约 14 ms 属于量具误差，不能算作"启动/退出"。

| 指标 | 旧（legacy） | **校准后** |

### E5. 旧规模外推作废

原表按 185.5 ms 线性外推（k=28 ≈ 25 min）**基数错误，作废**。按 6.18 ms 重算（仍为**估算，未实测**）：k=20 ≈ 198 ms、k=24 ≈ 3.2 s、k=28 ≈ 51 s；且 k≥24 时几十 GB 的文件读取本身会成为新下限。这张表既不能宣布目标可达，也不能宣布不可达。

### E6. 类目修正：`verify_profile` 的 `cleanup` 不等于全部析构

清理段只统计显式 `drop`。C 组（内存模式）因为多持有一份 4 MB 预读缓冲，cleanup 从 0.34 ms 升到 0.72 ms，`ru_maxrss` 从 12.3 MB 升到 15.9 MB —— 预读的成本没有被藏起来。

### E7. 负向证据的表述要收紧

原文"拒绝来自密码学校验，而不是解析错误"只在**已补做的分类证据**下成立。P2A 用 `--diag --trace-reads` 实测：public value 换值、proof 点元素换点、proof 域元素换值三种情况均**读满 105 次 / 3360 B 后**才被拒（`ConstraintSystemFailure`）；截断、非法点编码、非规范域元素则停在加载/解码阶段。原文那条 proof 比特翻转用例当时**没有记录底层错误类型**，不能单独作为"合法 proof 被密码学拒绝"的证据 —— 现由 P2A 的新用例替代。
