## 2 阻断 1：converter 缺方法与舍入未接通

### 2.1 v1 到底断了什么

```
生成器:  QUANT = '''  def _quantize_checked(self, arr, tensor_idx): ...'''   ← 定义了
         sub(METHODS + """  def to_dict(...)""")                              ← 只插 METHODS
候选:    tensor_data = self._quantize_checked(tensor_data, tensor_idx)   (654 行)
类体:    没有 _quantize_checked  ⇒ AttributeError
```

`py_compile` 通过完全不能说明问题 —— 它是运行期才炸。更糟的是**另外两条量化路径压根没接**：

| 路径 | 原写法 | 问题 |
|---|---|---|
| 主张量循环 | `(tensor_data * sf).round().astype(np.int64)` | v1 替换了，但方法不存在 |
| CUSTOM 权重 | `weights = (weights * sf).round().astype(np.int64)` → `adjusted_tensors` | v1 **没动**，绕过全部检查 |
| DIV | `np.array([(sf / div_val).round().astype(...)])` → `adjusted_tensors` | v1 **没动**，同样绕过 |

后两条走 `adjusted_tensors`，而 `to_dict` 在 662 行是 `if tensor_idx in adjusted_tensors: tensor_data = adjusted_tensors[tensor_idx]`，**直接跳过量检查**。也就是说 v1 即使补上方法，也仍有两条路能把 `NaN`/-inf 写进 msgpack。

### 2.2 v2 的改法

- E8 改成 `METHODS + QUANT + to_dict`，方法真的进类体；
- 三个量化点**全部**改为 `self._quantize_checked(...)`，后两处传 `already_scaled=True`（它们的值已经乘过 sf，再乘一次就是二次缩放）；
- 两层边界分开写、分开报错：
  - **L1 硬边界**：`[-2^31, i64::MAX−2^31]`，越界即拒绝；
  - **L2 主动策略**：`I32_POLICY` 常量，越界时错误文案明确写「这是本项目的保守选择，不是原编码的必要条件」。
- 比较**搬到整数域**：先 `round_half_away_from_zero` 得到整值，再 `astype(np.int64)`，然后拿整数比。原因是 float64 在 2^53 以上不能精确表示每个整数，直接 `float > 2^63` 会差几百到几千 —— 这条是我自己第一版写错、被自己的量级检查逼出来的。

### 2.3 验证：门禁 + 自测

**门禁不是摆设**，做了负向对照：

```
v1 候选 → 8 项失败

  ! [阻断1] _quantize_checked 调用点应为 3 处，实际 1
  ! [阻断1] round_half_away_from_zero 定义了但没有被调用
  ! [阻断2] to_dict 里仍有局部 padv2_evidence 赋值

```

`scripts/p4a_quant_selftest.py` 从候选里**按 AST 抽出** `round_half_away_from_zero` 与 `_quantize_checked` 的源码来跑（不导入 tensorflow、不跑转换），18 项全过。关键几条：

| 用例 | 结果 |
|---|---|
| `2.5` | half-away → **3**，numpy（half-to-even）→ 2 ⇒ 规则真的换掉了 |

| `2^54` | 拒绝（float64 已不能精确表示整数） |

## 3 阻断 2：证据生命周期

v1 的机制：`to_dict` 里 `padv2_evidence = []` 是**局部变量**，`_convert_padv2(..., padv2_evidence)` 往里 append；`to_msgpack` 却 dump `self.padv2_evidence`（`__init__` 里初始化的那个空列表）。**转换成功也只会写 `[]`**。

v2：

1. 容器统一到 `self.padv2_evidence`；`to_dict` 每次调用开头重置（含 `shared_metadata`、`_layer_op_idxes`、`_padv2_seen`、`_range`），避免复用实例时串场；
2. 证据记录**真实身份**，不再有 `pad_op=True` 这种占位：

```
op_idx / op_name / data_tensor / paddings_tensor / constant_tensor
constant('-inf'|0) / paddings[8] / producer_op_idx / producer_act
filter / stride / pad_h / pad_w
in_shape / pad_shape / pool_out_shape / pad_out_tensor / consumer_op_idx
n_consumers_in_subgraph / consumer_op_in_subgraph / is_subgraph_public_output
checked_against='exported_subgraph' / subgraph_range
```

3. 写盘时绑定这次转换的**实际产物**：

```json
{ "subgraph_range": [0, 10000], "padv2_count": 1,
  "model_sha256": "...", "config_sha256": "...",
  "shared_metadata_tensors": {...}, "evidence": [ ... ] }
```

4. `padv2_count` 与证据条数不一致、或有 PADV2 但证据为空 → 直接拒绝写盘。这条专门防「静默写空」。

## 4 阻断 3：稀疏 ID 与逐层可用性

### 4.1 为什么 v1 的 N4 是错的

v1 要求初始 `tensor_map` 含 `0..=max_key` 的**全部**键。但：

- 「删掉元数据张量、保留原 ID」本来就会留下**合法空洞**（例如删掉 PADV2 的 `45`/`1`）；
- 尚未执行到的层的输出，本来就不该作为初始张量存在；
- 而且这个 panic 位于 `assign_tensors_vec → tensor_map_to_vec` 的赋值路径，**不是可靠的加载门禁**：真要拦「删了张量没改 inp_idxes」，应该在一进 `generate_from_msgpack` 就拦。

### 4.2 v2 改成加载期两级校验

```rust
// 一级：逐层可用性（拓扑）
initial  = config.tensors[].idx ∪ config.inp_idxes
for (layer_idx, layer) in layers.enumerate():
    for idx in layer.inp_idxes:
        assert idx ∈ available                  // 否则报 layer 号 + tensor id
    available ∪= layer.out_idxes ; produced ∪= layer.out_idxes

// 二级：引用对账
referenced = inp_idxes ∪ ⋃layers[].inp_idxes ∪ out_idxes ∪ commit_before ∪ commit_after
for idx in referenced:
    assert idx ∈ initial ∪ produced             // 否则报「被引用但既非初始也无产出」
```

然后把 `referenced` 存进 `ModelCircuit` 的新字段 `referenced_tensor_ids`，供 `tensor_map_to_vec` 判定空洞是否合法：

```rust
match tensor_map.get(&i) {
  Some(t) => tensors.push(t.clone()),
  None => {
    if self.referenced_tensor_ids.contains(&i) {
      panic!("tensor {} 被引用但未被赋值；禁止用 smallest_tensor 静默填充", i);
    }
    tensors.push(smallest_tensor.clone());   // 未被引用的空洞：Vec 按 ID 索引，必须占位
  }
}
```

**为什么还保留占位**：这个 `Vec` 是按 tensor ID 索引的，空洞不填长度就对不上。但「被引用的 ID 落空」已经在一级/二级校验里被排除，且这里再兜一次 —— 占位只发生在**从未被引用**的位置上。

> 接口范围声明：本改动只动 `model.rs`（新增一个结构体字段 + 改 `tensor_map_to_vec`），**没有改 `dag.rs` 的签名**。若后续发现 DAG 存在未在 `layers` 里声明的隐式引用，本检查覆盖不到，需单独提 DAG 审计并另行批准。

v1 的 N5（把 `smallest_tensor` 改名 `_smallest_tensor` 以免 unused 警告）**撤回** —— v2 里它仍被使用。

## 5 阻断 4：图保护改到实际子图

### 5.1 v1 的具体漏洞

| 漏洞 | 机制 |
|---|---|
| 公开输出判错 | 用整图 `graph.Outputs`，但导出模型的公开输出是 `layers[-1]['out_idxes']`。`end_layer` 停在 PADV2 之后，Pad 输出**就是**公开输出，v1 查不出来 |
| 裁掉 ReLU 不报 | `start_layer` 落在 ReLU 之后，非负前提消失，v1 只查「前面有 ReLU」，不查那个 op 是否在子图内 |
| 元数据可能是运行时值 | `get_tensor()` 对非恒定 tensor 返回零输入 invoke 的结果；把它当 paddings 写进 params，等于把一条图依赖伪装成常量 |
| 几何检查缺失 | 没有 rank、没有 `paddings` 形状 `[4,2]`、没有非负、没有正核/stride、没有输入/Pad/Pool 三段 shape 核对 |
| 共享元数据一律拒 | 过度收紧：按引用位置清理即可，别的算子当数据用时它会经那个算子进 `keep_tensors` |

### 5.2 v2 的分层

**转换时（inline）**：P0 输入齐备 → P1b `paddings` 是静态常量且 `[4,2]` 非负整数、batch/channel 轴为 0 → P1 常量是静态常量且单元素 ∈ {−inf, 0} → P2 (−inf 时) 生产者 `fused_activation == RELU` **且 `producer_op_idx >= start_layer`** → P5 正核/stride、对称、每侧 < 核、三段 shape 自洽。

**转换后（post-pass，按实际子图）**：`_validate_padv2_subgraph(layers, start, end)`：

```
public = layers[-1]['out_idxes']（expose_output 时）
P4  pad_out_tensor ∉ public                     ← 用子图公开输出，不是整图
P3  子图内消费者数 == 1，且是转换时记录的那个 MaxPool
```

**静态常量**：`_static_constant()` 要求
`producer 不存在` ∧ `tensor.Buffer() != 0` ∧ `Buffers(bidx).DataLength() > 0`，否则拒绝 —— 有 producer 就是运行时值，不许冻结。

**几何**（轴顺序按 NHWC 解释，轴错会被 shape 等式挡住）：

```
paddings.shape == (4,2) 且全为非负整数
fh,fw,sh,sw > 0
ph0 == ph1 且 pw0 == pw1 且 ph0 < fh 且 pw0 < fw
pad_shape  == [in0+b0+b1, in1+ph0+ph1, in2+pw0+pw1, in3+c0+c1]
pool_shape == [pad0, (pad1-fh)//sh + 1, (pad2-fw)//sw + 1, pad3]
```

**元数据共享**：`_metadata_tensor_idxes` 不再抛异常，只从**本层** `inp_idxes` 去掉；共享情况记进 `shared_metadata`（写进证据）。别的算子仍把它当数据用的话，它会经那个算子的 `inp_idxes` 进 `keep_tensors`，继续被保留、继续被 commit —— 不误删。

**存活根**补全：`数据依赖 ∪ 模型输入 ∪ 整图输出 ∪ 导出子图公开输出`。v1 只有「数据依赖」，一个「既是常量又是图输出」的张量会被漏掉。

> 保守性说明：`_convert_padv2` 里仍按**整图**要求消费者恰好 1 个，比「只数子图内」更严。这是有意的 —— 宁可拒，不放过。

## 6 阻断 5：数值契约重写

### 6.1 loader 的真实精确域

`model.rs:297-302`：

```rust
F::from((x + 2^31) as u64) - F::from(bias as u64)
```

| x 区间 | 实际行为 |
|---|---|
| `[-2^31, i64::MAX − 2^31]` | `x+2^31 ≥ 0` 且不溢出 i64；`as u64` 精确；`F::from(u64)` 精确（u64 ≪ 域模数）；相减得到 x 本身（负值即 p+x，正是域编码）✅ |
| `x < −2^31` | `x+2^31 < 0` → `as u64` 补码回绕 → 编码成 `x+2^64`，静默改义 ❌ |
| `x > i64::MAX − 2^31` | `x+2^31` 溢出 i64（debug panic / release 回绕）❌ |

**上界是 9,223,372,034,707,292,159**，不是 2,147,483,647。v1 写的 `[-2^31, 2^31−1]` 只是「塞得进 i32」，被我当成了编码域。

### 6.2 因此 v1 的 `k ≤ 32` 撤回

v1 的推理是 `min_val = −(2^(k−1)) ≥ −2^31 ⇒ k ≤ 32`。前提（上界 2^31−1）一错，结论就没有依据 —— 而 `min_val` 走的是**另一条编码路径** `assign_constants` 里的 `F::from((val + shift) as u64) − F::from(shift)`，其中 `shift = −min_val·2 = 2^k`，根本不是 2^31。

v2 换成四条**各自独立**的检查：

| 条件 | 来源 | 精确值 |
|---|---|---|
| `global_sf > 0` | 显式要求（原代码没有） | — |
| `k ≥ 5` | `max_val = 2^(k−1) − 10 ≥ 0`（k=4 → −2） | 必要条件 |
| `k ≤ 62` | `assign_constants` 里 `-min_val * 2 = 2^k` 要能用 i64 表示 | 必要条件 |
| `k` 实用上界 | `num_rows = 2^k−9` 与 lookup 表规模 | **由资源决定，本批不给结论** |

### 6.3 S 与 2S 分开证

设 `S = sf²·2^17`：

| 层 | 要求 | 精确条件 | 对应 sf 上界 |
|---|---|---|---|
| 构造 `−S` | `S ≤ i64::MAX` | `sf²·2^17 ≤ 2^63−1` | **8,388,607**（≈2^23−1） |
| 使用 `2S` | `2S ≤ i64::MAX` | `sf²·2^18 ≤ 2^63−1` | **5,931,641** |
| 若 sf 是 2 的幂 | 同上 | `2m+18 ≤ 62` | **sf ≤ 2^22** |

v1 把 `sf²·2^18` 当成「原 shift 构造的精确边界」，其实它对 `−S` 这一步是**保守**的；而 `sf ≤ 2^22` 只在 sf 为 2 的幂时成立，一般 sf 的界是 5,931,641（> 2^22 = 4,194,304）。所以直接写 `sf ≤ 2^22` 会误拒 (2^22, 5931641] 这一段。

另外原代码 `-(config.global_sf * config.global_sf * (1 << 17))` 是 **i64 乘法**，release 下溢出静默。v2 把它改成 `i128` + `checked_mul` 链，并且**结构体字面量里直接用这条链算出的值**，不再重写一遍未检查的乘法。

### 6.4 Max 差值 lookup 域

v1 我一直没定死这条。现在从 `InputLookupChip::load_lookups` 读出来：

```rust
for i in 0..self.config.num_rows as i64 {
  table.assign_cell(..., || Value::known(F::from(i as u64)))    // 裸无符号
}
```

表里是 `0, 1, ..., num_rows−1` = `0 ..= 2^k−10` 的**裸无符号值**，不是带符号移位值。Max 的两个 lookup 是 `outp − inp1`、`outp − inp2`：负差值会成为巨大域元素，不在表内。所以**差值域就是 `[0, 2^k−10]`**。

顺带记下 Max 自己的宿主域：`convert_to_u64(&(v + S))` 要求 `−S ≤ v < 2^64 − S`。两条都写进 manifest。

### 6.5 仍未闭合的

- 各 gadget 自己的 `min_val/max_val` 派生域（ReLU / Div / BiasDiv / Update 各不相同），本批只做了 Max 一条；
- `2S` 的真实出现位置：只从 `bias_div_round_relu6` 的 `let div_inp = 2 * inp + div_val;`（其中 `inp = x + S`）确认了这种形态存在，**没有逐个 gadget 复核**。

## 7 阻断 6：窗口几何与负例

### 7.1 本图的归约长度恒为 9

`max_pool_2d.rs` 的 `splat` 确实会在越界时跳过 —— 但本图的池化是**显式** `PADV2(-inf)` + `VALID`：padded 尺寸 = `H+2`，窗口 `3×3 / stride 2` 全部落在 padded 张量内部，**没有一次越界访问**。因此：

> 本图 Rust 侧 Max 归约的输入长度**恒为 9**，不存在 4/6。

v1 把「内部 9 / 边缘 6 / 角 4」当成 `MaxPool2D` 的实际调用长度，是把「PyTorch 隐式 pad 的池化」和「显式 Pad + VALID」混了。4/6 仍然有用 —— 但只能作为**独立长度测试**（验证候选修复对任意长度成立），不能当作本图的路径。

### 7.2 真正的全填充反例

v1 用的 `pad=2, kernel=3` 有两处错：

1. 它**不必**产生全填充窗：padded 尺寸 = `H+4`，首窗覆盖 padded 的 `[0:3]`，其中原图元素是 `[0:1]` 那一段 —— 仍有真实元素；
2. 它**不会**被 `<kernel` 检查拒绝：`ph0 = 2 < fh = 3`，条件成立。

正确的构造是让**首窗完全落在填充区**：

```
H = W = 1, pad = 3, kernel = 3, stride = 1
→ padded = 7×7，首窗取 padded[0:3, 0:3]
→ 原图只有 (0,0) 一个元素，落在 padded[3,3]，不在首窗内
→ 首窗 9 个位置全是填充
```

这时 0 填充与 −inf 填充给出不同结果（0 vs −inf），降级不成立。这条替换进 P4-B 矩阵。

### 7.3 P5 条件的定位

`ph0 < fh` 保留，但它的作用只是排除「填充量 ≥ 核」这种明显病态，**不足以**判定全填充窗 —— 全填充窗的判定必须按具体窗口几何（上式）。两个条件都要，不能互相替代。

## 8 门禁与自测汇总

| 检查 | v1 | v2 | 性质 |
|---|---|---|---|
| converter AST 门禁 | **8 项失败** | 0 项 | 结构级：方法存在性、调用点数、容器归属、字段存在 |
| model 文本门禁 | **14 项失败** | 0 项 | 文本/结构级：关键词、禁用模式、字段出现次数、括号配平（已排除注释与字符串） |

门禁本身的**负向对照**是本批最该保留的东西：v1 那 22 项失败，就是 v1 交付时应该被拦住但没拦住的东西。

**必须说清的边界**：model 侧是**文本门禁**，不是类型检查。`matches!(s, Some(v) if ...)`、`checked_neg()`、`as i64` 这些写法能否通过借用检查与类型推断，只有 `cargo check` 才知道 —— 那是 P4-B 第一件事。
