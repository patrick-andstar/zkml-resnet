## 4. 结果

清单：`manifests/p4b-compile-and-max.json`。远端日志：`$REPRO/logs/p4b/`。

### B0 · pristine 基线 [实测]

`cargo check --locked -j 4` → **rc=0，15.05 s**。仅 2 条上游自带警告（`unused dependency halo2` / `serde_json`）。

意义：基线本身可编译，因此后续任何失败都能归因到候选，而不是环境。

### B1 · + max_reduce_fix [实测]

`cargo check` → **rc=0**。无新增警告。应用后 `src/gadgets/max.rs` = `970928e8…`。

### B2 · + model_numeric_contract_v2 [实测]

首轮 **rc=101，1 个错误**：

```
error[E0382]: borrow of moved value: `config.tensors`
   --> src/model.rs:512:38
382 |       for flat in config.tensors {          ← move
512 |       let initial_ids: BTreeSet<i64> = config.tensors ...  ← 借用
```

这正是补正批次反复声明的边界：**文本门禁过不了借用检查**。

修正只有 1 处，且是编译器自身建议的形式：

```rust
-    for flat in config.tensors {
+    for flat in &config.tensors {
```

修正后 **rc=0**。升为 v3：`patches/model_numeric_contract_v3.rs`（`19008b73…`）、增量补丁 `patches/model_numeric_contract_v3.diff`（452 B，单 hunk）。

**结论：整份 model 候选只差这一行，其余全部通过类型与借用检查。** 这比预期好——说明文本门禁对语法/API 的判断基本可靠，漏的只是所有权。

### B4 · Max 最小用例 [实测，但只是有限子集]

用例设计（`local_bins/p4b_max_test.rs`，`49b6337e…`）：

- 输入按 model 的 `to_field` 同一编码写入 advice（含负值）；
- 输出用 **`constrain_instance` 钉住宿主参考 `max`**——算错必然让 MockProver 失败，不靠人工读值；
- 每个用例再跑一次「期望值 +1」的负向对照，**必须被拒**，否则该用例不记 PASS。

矩阵：9 个向量 × `num_cols ∈ {3, 6, 12}`（即 G=1/2/4）× 正负对照 = 54 次 MockProver(k=12)。

**候选（max_reduce_fix）：TOTAL PASS，27/27 全部通过，负向对照全部被拒。**
**原版 `max.rs`（`1e60cd14…`，从备份还原后重跑同一份测试）：TOTAL FAIL。**

| 列数 | 原版失败用例 | 候选 |
|---|---|---|
| 3（G=1） | 无 | 全过 |
| 6（G=2） | `[0,1]`、`x1=1 其余 0` | 全过 |
| 12（G=4） | `[0,1]`、`x1=1 其余 0`、`[1,2,3]`（奇数长度） | 全过 |

#### B4.1 必须更正的两处表述

1. **「G≥2 才能让 Max 正确」是反向解读，撤回。** 实测是**候选在 G=1/2/4 全部通过**，失败的是**原版**且只在 G≥2。所以 6 列不是候选正确性的必要条件，3 列也不构成"不支持"的证据。列数改动仍须按配置另验，但不能拿这句话当理由。
2. 源码注释写的「9元素逐位置最大」与实际不符——见下面的覆盖表，唯一最大值只测了位置 0、1、8。

#### B4.2 覆盖矩阵（诚实版）

| 项目 | 已覆盖 | 未覆盖 |
|---|---|---|
| 9 元素唯一最大位置 | 0、1、8 | **2–7** |
| 长度 | 1、2、3、5、9 | **4、6、7** |
| 全负窗口 | 无（`[-5,-1,-3,-16,0]` 含 0） | **全负** |
| 列数 | 3、6、12（G=1/2/4） | **9（G=3）** |
| 拒绝契约 | 无 | **空输入、非法列数** |
| 数值边界 | 无 | **Max 差值上界 `2^k−10` 与上界+1** |
| Pad→Max | 无 | **合成图、非负前提失效、额外消费者** |

因此本批只能记 **「Max 有限子集通过」**，§P4-B.2 **未完整验收**；这些缺口不能藏进未开始的 §.3/.4。

#### B4.3 小测参数与生产参数的差异

手工设 `k=12, num_rows=1000, shift_min_val=+64`，因此查表实际是 **[0, 999]**，不是生产派生公式在 k=12 时的 `[0, 2^k−10]=[0,4086]`。两者必须分开登记，不能混用。

更要紧的一处：`max.rs` 用 `F::from((-self.config.shift_min_val) as u64)` 作偏移，`+64` 经取负再 cast 得到的是 `2^64−64`，不是正 64。本批输入都 ≤ 9，`v + (2^64−64)` 落在单 limb 内，所以结果正确；但**输入 64 会使和变成 `2^64`，超出 `convert_to_u64` 的单 limb 接受范围而 panic**（静态推导，未实跑）。未来做差值边界测试必须先选合法偏移，并区分"宿主转换失败"与"lookup 按预期拒绝"——这两者的日志形态不同，不能都记成"被拒"。

- 不能把小 k 的 MockProver 结论外推到目标配置。
- 不能把 `cargo check` 的耗时当作 `cargo build --release` 或 prove 的耗时。
